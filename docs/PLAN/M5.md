# M5. 게임 목록과 이어하기

## 목표

GET /games와 게임의 저장된 여정 화면을 연결한다.

## 이번 단계에서 이해할 것

정렬 조회, 요약 DTO, 이어하기

## 구현 순서

- [o] GameRepository.findAllByOrderByIdDesc를 작성한다.
- [o] GameSummaryResponse에 기본 게임 필드를 담고 deck은 제외한다.
- [o] GET /games를 실제 Repository 조회까지 연결한다. DB가 비었을 때만 빈 배열이 나온다.
- [o] 조회 서비스에 readOnly 트랜잭션을 적용한다.
- [o] 실제 게임에서 생성·진행·새로고침·여정 선택을 함께 확인한다.

## 질문

### 목록과 상세 응답이 다른 이유는?
- 각 API와 UI가 필요로 하는 데이터가 다름.
- 목록의 경우 게임을 구분하는 기본 정보만 필요하기에 덱을 제외한 GameSummaryResponse 사용.
- 이어하기는 실제 상태 복원이 필요하기에 덱까지 포함한 GameDetailResponse 사용.

### 정렬 메서드 이름이 어떤 조회를 만드는가?
- 전체 Games 조회 Id를 내림차순.

### 이어하기 버튼부터 DB 조회까지 어떤 경로를 지나는가?
1) 저장된 여정 목록 조회
- 타이틀 화면
-> GET /games
-> GameController.getGames()
-> GameService.getGames()
-> GameRepository.findAllByOrderByIdDesc()
-> MySQL의 games 테이블 조회
-> List<GameSummaryResponse>
-> 저장된 여정 목록 표시

2) 저장된 여정 선택
- 목록 조회 화면
-> GET /games/{gameId}
-> GameService.getGame()
-> GameRepository.findById(gameId)
-> RunCardRepository.findAllByGameOrderByIdAsc(game)
-> games와 run_cards 데이터 조회
-> GameDetailResponse
-> Hp, 층, phase, status, deck 복원
