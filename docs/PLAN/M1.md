# M1. 도메인과 DB 관계

## 목표

Game·RunCard의 단방향 관계와 테이블을 이해한다.

## 이번 단계에서 이해할 것

Entity, PK·FK, IDENTITY, 단방향 ManyToOne

## 시작 조건

M0의 결과와 남은 문제를 확인한다. 선행 실행 기반이 막히면 독립 작업만 진행하고 완료 판정을 미룬다.

## 구현 순서

- [ ] 기존 GamePhase·GameStatus·Game·RunCard를 같은 패키지에서 직접 작성한다.
- [ ] Game의 IDENTITY ID, 문자열 enum, JPA용 기본 생성자, 초기값 생성자를 확인한다.
- [ ] RunCard → Game에 LAZY·optional=false·game_id FK를 둔다. Game에 카드 컬렉션은 추가하지 않는다.
- [ ] 기존 Repository 계약을 유지한다. 아직 필요하지 않은 계층·인터페이스를 확장하지 않는다.
- [ ] MySQL의 두 테이블·FK를 확인하고 관계를 그림이나 문장으로 기록한다.
