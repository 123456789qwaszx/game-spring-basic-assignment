# M3. 게임 상세 조회

## 목표

GET /games/{gameId}로 저장 데이터를 다시 읽는다.

## 이번 단계에서 이해할 것

Repository 조회, DTO 조립, 읽기 트랜잭션

## 구현 순서

- [o] 게임 ID로 조회하고 없으면 404를 반환한다. Lv 8에서는 기존 ResponseStatusException 방식을 사용할 수 있다.
- [o] 해당 Game의 카드를 findAllByGameOrderByIdAsc로 조회한다.
- [o] 조회 트랜잭션 안에서 GameDetailResponse로 조립하고 200을 반환한다.
- [o] M2의 POST와 별도 GET 요청으로 결과를 비교하고, DB에도 같은 데이터가 있는지 확인한다.

## 질문

### 카드 정렬과 게임별 구분은 어디서 정해지는가?
- List<RunCard> findAllByGameOrderByIdAsc(Game game);

- @JoinColumn이 만들 Column을 통해 게임을 구분함.
- ByGame에 Game을 넘기지만, SQL에서 game_id = ?인 상태.
- 그때 Hibernate가 객체에서 id만 꺼내 씀.
- Game에 cards 컬렉션이 없으니, 꺼낼 방법이 제한됨. 레포지토리로 명시적으로 조회해야함.

### DTO 조립을 Service에서 끝내는 이유는?
- 트랜잭션 경계 안에서 끝내야 함.
