# M3. 게임 상세 조회

## 목표

GET /games/{gameId}로 저장 데이터를 다시 읽는다.

## 이번 단계에서 이해할 것

Repository 조회, DTO 조립, 읽기 트랜잭션

## 시작 조건

M2의 결과와 남은 문제를 확인한다. 선행 실행 기반이 막히면 독립 작업만 진행하고 완료 판정을 미룬다.

## 구현 순서

- [ ] 게임 ID로 조회하고 없으면 404를 반환한다. Lv 8에서는 기존 ResponseStatusException 방식을 사용할 수 있다.
- [ ] 해당 Game의 카드를 findAllByGameOrderByIdAsc로 조회한다.
- [ ] 조회 트랜잭션 안에서 GameDetailResponse로 조립하고 200을 반환한다.
- [ ] M2의 POST와 별도 GET 요청으로 결과를 비교하고, DB에도 같은 데이터가 있는지 확인한다.
