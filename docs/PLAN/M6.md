# M6. 이름 변경과 삭제

## 목표

PATCH·DELETE로 변경 감지와 자식 삭제를 확인한다.

## 이번 단계에서 이해할 것

변경 감지, FK 관계, 삭제 순서

## 구현 순서

- [o] RenameRequest에 이름 공백 금지·2~12자 검증을 작성한다.
- [o] PATCH는 쓰기 트랜잭션에서 조회 → game.rename → 204. 불필요한 save 없이 DB 반영을 확인한다.
- [o] DELETE는 쓰기 트랜잭션에서 게임 조회 → 해당 RunCard 삭제 → Game 삭제 → 204로 작성한다.
- [o] 없는 게임은 404. 이름 변경은 다른 진행 필드와 카드 ID를 바꾸지 않는다.

## 질문

### save를 추가 호출하지 않아도 이름이 저장되는 이유는?
- renameGame()이 @Transactional 안에서 실행되기 때문.
- Hibernate가 더티체킹을 수행해서.

### 왜 자식부터 삭제하는가?
- run_cards.game_id가 games.id를 외래 키로 참조하고 있기 때문.
- 카드가 남아 있는 상태에서 부모인 Game부터 삭제하면, 카드가 존재하지 않는 게임을 참조하게 됨.
- DB는 참조 무결성을 지키기 위해 부모 삭제를 거부함.
- 따라서 해당 게임의 RunCard를 먼저 삭제한 뒤 Game을 삭제해야 함.
- 두 작업을 하나의 트랜잭션으로 묶어 중간에 실패하면 모두 롤백되도록 함.
