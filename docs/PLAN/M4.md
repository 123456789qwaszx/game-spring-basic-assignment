# M4. 진행과 전체 덱 저장

## 목표

PUT /games/{gameId}/progress로 진행과 전체 덱을 함께 저장한다.

## 이번 단계에서 이해할 것

트랜잭션, 영속 상태 변경, 전체 덱 교체

## 시작 조건

M3의 결과와 남은 문제를 확인한다. 선행 실행 기반이 막히면 독립 작업만 진행하고 완료 판정을 미룬다.

## 구현 순서

- [ ] ProgressRequest의 HP 0~99·층 1~10·필수 phase/status·비어 있지 않은 deck을 검증한다.
- [ ] 게임 조회 → 진행 필드 변경 → 기존 카드 삭제 → 요청 전체 덱 저장 → 상세 DTO를 작성한다.
- [ ] 위 작업 전체를 public Service 메서드 하나의 쓰기 트랜잭션으로 묶는다.
- [ ] Game ID와 이름을 유지하고 새 카드 ID를 응답한다.
- [ ] 같은 PLAYING 요청을 반복하여 카드 수·내용·순서를 확인한다.

## 내가 설명할 수 있어야 함

- [ ] 왜 전체 덱 교체인가?
- [ ] 왜 Service 메서드 하나가 트랜잭션 경계인가?
- [ ] 조회한 Game 변경에 save가 반드시 필요한가?
- [ ] 중간 실패 시 왜 함께 롤백되어야 하는가?

## 학습 경계

Game 변경·카드 삭제·삽입의 원자성을 이해한다. 실패 주입 자동 테스트는 이번 필수가 아니며, 수행하지 않은 롤백은 검증했다고 쓰지 않는다. 종료 상태 409도 이번 구현 범위에 넣지 않는다.
