# M2. 게임 생성과 입력 검증

## 목표

POST /games를 요청부터 DB까지 완성한다.

## 이번 단계에서 이해할 것

DTO, Bean Validation, 쓰기 트랜잭션

## 시작 조건

M1의 결과와 남은 문제를 확인한다. 선행 실행 기반이 막히면 독립 작업만 진행하고 완료 판정을 미룬다.

## 구현 순서

- [ ] CreateRequest·RunCardRequest와 CardResponse·GameDetailResponse를 작성한다.
- [ ] playerName은 공백 금지·2~12자, deck은 비어 있지 않게, 내부 카드 검증을 연결한다.
- [ ] cardType은 공백 금지 String, acquiredFloor는 Integer·필수·0~10으로 검증한다.
- [ ] 쓰기 트랜잭션에서 Game 저장 → 요청 순서대로 카드 저장 → 카드 ID 오름차순 조회 → 상세 DTO를 조립한다.
- [ ] Game 초기값은 99·1·REWARD·PLAYING. 시작 덱은 POST 요청을 저장하고 서버에서 9장을 만들지 않는다.
- [ ] POST /games를 201로 연결하고 기존 ErrorResponse·400 핸들러를 유지한다.
