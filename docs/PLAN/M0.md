# M0. 환경과 실행 기반

## 목표

Docker MySQL 연결과 애플리케이션 부팅을 확인한다.

## 이번 단계에서 이해할 것

설정, Bean 등록, 생성자 주입

## 시작 조건

기존 파일·static·Gradle 설정을 보존하고 작업 브랜치를 확인한다.

## 구현 순서

- [o] JDK 21과 Gradle wrapper 실행을 확인한다.
- [o] Docker MySQL의 포트·DB·계정·volume을 정하고 연결을 확인한다.
- [o] application.properties에 datasource·개발용 ddl-auto=update·show-sql·open-in-view=false를 설정한다. 실제 비밀번호는 환경 변수로 전달한다.
- [o] 기존 클래스와 패키지를 유지하고 @Service·생성자 주입을 정상 연결한다.
- [o] 기존 Entity를 보존한 상태에서 부팅한다. 정적 HTML 제공과 게임 타이틀 정상 동작은 구분한다.

## 질문

### Spring이 GameService를 생성하고 Controller에 전달하는 과정은?
-> @SpringBootApplication에 포함된 @ComponentScan이 메인 클래스가 있는 패키지를 검사.
-> 클래스 파일에 @Component 계열 어노테이션(@Service, @Repository, @Controller, @RestController)이 있느지 확인.
- 이 단계에서 객체를 생성하진 않음.
- 이런 이름의 빈을 특정 타입과 생성자로 만들 수 있도록 BeanDefinition에 등록만 함.

-> GameController의 Lombok의 @RequiredArgsConstructor가 있고, 이게 final GameService gameService 필드를 받는 생성자를 컴파일 시점에 만들어둠.

-> GameController를 만들기 위해,
   컨테이너는 생성자에 넣을 GameService 빈을 먼저 만듬.

-> 타입 GameService로 컨테이너에서 빈을 찾는다.
-> 생성한 인스턴스를 그대로 주는 대신, 그것을 감싼 서브 클래스를 만들어 등록.
   추가 어노테이션 동작을 담당.
-> 이 프록시 객체가 GameController 생성자에 들어가 필드에 박힘.

### 설정 파일과 환경 변수는 각각 무엇을 정하는가?
> 환경변수: 
docker run -e MYSQL_ROOT_PASSWORD=1234 -e MYSQL_DATABASE=game_c ...
- MySQL 공식 이미지는 첫 실행 시 초기화를 돌리는데, 이 환경 변수를 읽음.

> 설정파일: 
spring.datasource.url=jdbc:mysql://localhost:3307/game_c
spring.datasource.username=root
spring.datasource.password=1234
- 접속하라는 주소.

### 정적 페이지가 보이는 것과 API가 정상이라는 것은 어떻게 다른가?
둘의 경로가 다름

> 정적 페이지 경로:
- src/main/resources/static/에 있는 index.html,JS,CSS는 SpringBoot가 ResourceHttpRequestHandler로 그냥 파일을 내려줌.
- 즉 파일이 존재하고 웹 서버가 살아있으면 뜸.

> API 응답 경로:
- DispatcherServlet -> HanlderMapping -> Controller -> Service -> Repository -> DB
- 전부 통과해야 200이 나옴.
